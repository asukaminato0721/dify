- The remaining Flask imports are concentrated in copied legacy generator/controller paths that are no longer on the active public FastAPI route surface.

Immediate blockers
------------------
- Large parts of the copied code still assume:
  - Flask request/session globals
  - Flask-Login
  - sync SQLAlchemy sessions via `db.session`
  - Flask-specific controllers and decorators
- Many services import broad legacy modules rather than small interfaces, so route-by-route porting still requires extracting local async models/services under `api_server/`.
- Model-provider resolution and the broader generation feature set still depend on copied legacy domain code in places, so the async-native generation slice is only partially ported compared with the original Flask feature set.
- The remaining unfinished work is concentrated in moving workflow-backed generation persistence/response flows onto the new async execution surface end to end and shrinking the remaining sync companion-engine seams underneath the copied runtime.

Next steps
----------
1. Continue porting the next public route family.
   - Candidate next slice: move the public workflow-backed generation persistence/response flow from sync companion helpers to async-native execution/persistence services.
   - Prefer local async models/services under `api_server/` rather than extending Flask-era services.

2. Expand the FastAPI-native domain layer.
   - Continue extracting minimal async models/services for features actually exposed by routes.
   - Keep new runtime code under `api_server/` instead of extending Flask-era modules.

3. Port controller groups incrementally.
   - Bootstrap/authentication
   - Console public endpoints
   - Web public endpoints
   - Console authenticated endpoints
   - Service API endpoints

4. Replace sync DB access.
   - Eliminate the remaining sync companion-engine dependencies from active FastAPI code paths after the copied workflow runtime is ported end to end.
   - Move active repositories/services to `AsyncSession`.

5. Replace Flask-specific infrastructure.
   - Auth/session wrappers
   - Error translation
   - request-context helpers
   - extension bootstrapping

6. Widen verification after each slice.
   - `pyrefly` on the active FastAPI package
   - pytest on newly ported routes/services
   - only after a package is active, run broader type coverage on it
